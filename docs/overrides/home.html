Everything your agents don't tell you.

Each harness shows one session at a time. agent-top lines them all up, from the live terminal view to a month of history.

agent-top

Who is working, who is waiting.

A terminal table of every agent process, with its state, tokens, burn rate and cost, and a detail pane for the one you pick.

  • Subagents nested under their parent
  • Tool calls that never came back
  • Rate-limit windows for Codex
$ agent-top
MCP servers

Servers left running after the agent quit.

Each MCP server's calls, errors, CPU and memory, joined to its process. An orphan turns red and says which agent it came from.

  • One row per server, per agent
  • npx and uvx wrappers counted once
$ agent-top mcp
agent-top report

What it all cost.

Tokens and dollars at list price, by harness, model, project or day, from the transcripts already on disk.

  • Unpriced tokens shown, never guessed
  • Cache reads and writes split out
  • JSON for your own scripts
$ agent-top report --by model
agent-top ui

A local dashboard for the history.

Overview, report, sessions and tools, served on 127.0.0.1 from the local store. Open a session for its run graph and turns.

  • Read-only, no login, no cloud
  • CSV export
$ agent-top ui
Context timeline

Where the context window went.

Every turn's context, split by source, with compactions marked. See which files and tool results filled it.

  • Claude Code, Codex and OpenCode
  • Subagents on their own track
$ agent-top ui → Sessions
serve --listen

Agents you built yourself.

Point any OpenTelemetry SDK at agent-top and its spans join the store, priced from the same table as the coding agents.

  • OTLP over HTTP, JSON or protobuf
  • Works from a container
$ agent-top serve --listen 127.0.0.1:4318

Nothing to install in your agents.

agent-top reads what is already on your disk and in your process table. Your transcripts stay on your machine.

Transcripts

The JSONL and SQLite files each harness writes, parsed for tokens, models, tool calls and timing.

Process table

Which agent owns which child, so MCP servers and shells are counted, and orphans are caught.

A local store

One SQLite file for history: sync to fill it, sql to query it, ui to browse it.

Counted exactly

  • Tokens per model, per session
  • Cache reads, writes and output, split
  • When each session ran, and in which project

Estimated, as a range

  • Energy per token, from your table
  • Grid carbon intensity
  • Data-centre overhead (PUE)

Not published by anyone

  • Energy of a Claude or GPT token
  • What a cache read costs
  • Which region served a request

agent-top ships no coefficients: you write ~/.config/agent-top/energy.toml with a source for each figure.
